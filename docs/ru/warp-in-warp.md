# WARP-in-WARP

[← Назад к README](../../README_RU.md)

`-through` гоняет весь скан изнутри другого туннеля WARP. Внутренний туннель выходит из сети Cloudflare там же, где внешний, поэтому `SEEN AS` показывает регион ноды внешнего эндпоинта, а не ваш.

## Как собрать цепочку

1. Найдите эндпоинт с зарубежной нодой обычным сканом. Если подойдёт любая нода за пределами своей страны:

   ```sh
   warpscout scan -p awg -exclude-country RU -best
   ```

   Если нужна конкретная:

   ```sh
   warpscout scan -p awg -node FRA -best
   # 188.114.97.177:2408
   ```

2. Просканируйте через него:

   ```sh
   warpscout scan -p awg -through 188.114.97.177:2408
   ```

Все эндпоинты второго прогона выходят в стране этой ноды. Та же сеть, которая напрямую сканируется как `RU`, но через эндпоинт на `FRA`:

![Скан WARPSCOUT через другой туннель WARP](../../.github/assets/warpscout-through.png)

## Какой протокол где

`-p` означает ровно то же, что и везде: протокол туннеля, который идёт по вашей сети. Под `-through` это внешний туннель - единственный, который вообще видит DPI:

```
[хост] --( -proto: идёт по вашей сети, его и видит DPI )--> внешний эндпоинт --( -inner-proto: внутри внешнего туннеля, не виден )--> сканируемые эндпоинты
```

Если обычный скан на этой сети требует `-p awg`, то его требует и вложенный. Новый флаг здесь только `-inner-proto`, и по умолчанию он `wg`: внутри внешнего туннеля маскировка не требуется и лишь съедает MTU.

## Что нужно знать

- `register` заводит второе устройство WireGuard для внешнего туннеля: WARP не даёт вложить два туннеля с одним приватным ключом. Если файл аккаунта создан версией младше `0.12.0`, перезапустите `warpscout register`.
- Скан ограничивается одним туннелем за раз (`-jt 1`): внутренние туннели делят одно внешнее устройство, и уже при `-jt 3` Cloudflare начинает отдавать ложно-отрицательные результаты. Поэтому вложенный скан заметно медленнее обычного.
- MASQUE в цепочке не участвует ни с одной стороны: там нельзя выбрать ноду, а выбор ноды для внешнего туннеля - весь смысл упражнения.
- `ENDPOINT PING` под `-through` измеряется по пути `[хост] → [внешний эндпоинт] → [внутренний эндпоинт]`, то есть хоп до внешнего эндпоинта входит в замер. Ранжировать по нему `-best` всё равно можно.

## Конфиг для цепочки

`-conf` для такого прогона пишет оба туннеля.

```sh
warpscout scan -p awg -through 188.114.97.177:2408 -conf warp.yaml -conf-type mihomo
```

Под `-conf-type mihomo` результат самодостаточен: два прокси, у внутреннего `dialer-proxy`, цепочку собирает сам mihomo. Обычный `.conf` цепочку выразить не умеет, поэтому там два интерфейса подряд - их надо разложить по двум файлам и связать средствами клиента, об этом сказано комментарием в шапке файла.

Проверить цепочку, не собирая интерфейсы руками, можно командой [`socks`](socks.md) - она тоже принимает `-through`.
