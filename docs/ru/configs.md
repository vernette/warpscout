# Конфиги и фильтры

[← Назад к README](../../README_RU.md)

## Один адрес в вывод

`-best` заменяет таблицы одной строкой `ip:port`, так что команду легко вставить в скрипт или пайп:

```sh
warpscout scan -p awg -best
# 188.114.98.58:2408
```

## Фильтры

`-node` оставляет только эндпоинты, попадающие на заданные ноды, `-country` - только те, чья нода находится в заданных странах. Оба принимают списки через запятую:

```sh
warpscout scan -p awg -country DE,NL -best
warpscout scan -p awg -node HEL,ARN -best
```

`-exclude-node` и `-exclude-country` - то же самое наоборот. Они складываются с положительными фильтрами, ради чего и заведены: оставить страну, выбросив одну её ноду.

```sh
warpscout scan -p awg -exclude-node DME -best
warpscout scan -p awg -country SE,DE -exclude-node ARN -best
```

Если после фильтров ничего не осталось, команда завершается ошибкой.

## Конфиги

`-conf` пишет готовый к импорту конфиг для единственного лучшего эндпоинта прогона, в том же протоколе, которым шёл скан:

```sh
warpscout scan -p awg -country DE -conf warp.conf
```

`-conf -` печатает конфиг в терминал, чтобы скопировать его или направить в пайп:

```sh
warpscout scan -p awg -conf -
warpscout scan -p awg -conf - > warp.conf
```

| Флаг          | Что делает                                                                     |
| ------------- | -------------------------------------------------------------------------------- |
| `-table-off`  | Конфиг не трогает маршруты. Нужно, если маршрутизируете трафик сами              |
| `-mtu N`      | Прописать `MTU`. Без флага строка не пишется, и клиент выбирает значение сам      |
| `-dns A,B`    | Заменить резолверы своим списком (по умолчанию `1.1.1.1, 1.0.0.1`)                |
| `-no-dns`     | Убрать строку DNS вообще, клиент оставит системные резолверы                      |

```sh
warpscout scan -p awg -conf warp.conf -table-off
warpscout scan -p awg -conf warp.conf -mtu 1280
warpscout scan -p awg -conf warp.conf -dns 9.9.9.9,149.112.112.112
```

### Форматы

`-conf-type` выбирает формат:

| Значение      | Что получится                                                                                        |
| ------------- | ------------------------------------------------------------------------------------------------------ |
| `native`      | По умолчанию: `.conf` для `wg`/`awg`, `config.json` для [usque](https://github.com/Diniboy1123/usque) под MASQUE |
| `mihomo`      | Блок `proxies:` для [mihomo](https://github.com/MetaCubeX/mihomo), который умеет и AmneziaWG, и MASQUE   |
| `mihomo-json` | Те же прокси JSON-массивом                                                                              |

```sh
warpscout scan -p awg -conf warp.yaml -conf-type mihomo
warpscout scan -p masque -conf warp.yaml -conf-type mihomo
warpscout scan -p awg -conf - -conf-type mihomo-json | jq '.[0]'
```

## Свои адреса

`-target` сканирует указанные адреса вместо встроенных пулов. Принимает отдельные IP-адреса, диапазоны CIDR или их смесь через запятую:

```sh
warpscout scan -p awg -target 188.114.98.58
warpscout scan -p awg -target 188.114.98.0/28
warpscout scan -p awg -target 188.114.98.58,162.159.192.0/28
```

Диапазоны IPv4 шире `/20` отклоняются, смешивать IPv4 с IPv6 в одном запуске нельзя.

## Замер скорости

`-speed` добавляет колонку `SPEED` - скорость скачивания внутри туннеля:

```sh
warpscout scan -p awg -P -speed
```

Это отдельная фаза после скана, и меряет она по одному эндпоинту за раз - иначе замерялась бы ширина вашего канала, делённая на число туннелей. Меряются ровно те эндпоинты, которые попадают в вывод: лучший в каждой подсети для таблицы на экране плюс лучший на каждой ноде для файла отчёта. У остальных строк остаётся `-`, фаза стоит примерно трёх секунд на эндпоинт.

![Фаза замера скорости WARPSCOUT](../../.github/assets/warpscout-speed.png)

Число - это скорость одного потока; браузерный спидтест открывает несколько сразу и может законно показать больше. Разброс между эндпоинтами - ожидаемая картина, а не симптом.

Сам по себе флаг порядок сортировки не меняет: она по-прежнему идёт по потерям и пингу. Чтобы ранжировать по скорости, нужен `-best-by speed`:

```sh
warpscout scan -p awg -best -best-by speed
```

Этот флаг сам запускает фазу замера, так что скан идёт столько же, сколько с `-speed`. Набор замеряемых эндпоинтов по-прежнему выбирается по пингу, то есть `-best-by speed` даёт самый быстрый **из этих выбранных**, а не из всех просканированных.

## Файл отчёта

Кроме таблиц на экране WARPSCOUT пишет файл `warpscout-report-<дата>.txt`: закомментированная шапка, дальше все рабочие эндпоинты, дальше разорванные, в конце лучший эндпоинт каждой ноды. Плоский список без рамок, легко обрабатывается `awk` и подобным.

`-o FILE` меняет имя, `-no-report` отключает файл. `-best` и `-conf -` отключают его сами, а `-o` возвращает обратно.
